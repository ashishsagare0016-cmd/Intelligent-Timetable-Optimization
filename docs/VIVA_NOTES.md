# Intelligent Timetable Optimization - Viva Examination Guide

This document contains 34 beginner-friendly questions and answers designed to help you excel during your college DAA / Capstone project viva examination.

---

### Q1: What is the main purpose of the project?
**Answer**: The main purpose is to automate college timetable generation, prevent resource conflicts (teacher, room, and student overlaps), evaluate hard and soft constraints, optimize timetable quality using local search, provide explainable slot decision rationales, and allow interactive What-If move simulations.

### Q2: Why did you choose timetable optimization?
**Answer**: Manual timetable creation is extremely time-consuming, prone to human error, and rarely optimized for teacher gaps or student workload. Timetable scheduling is a classic NP-hard DAA problem that combines graph theory, recursive search, and optimization.

### Q3: What is graph colouring?
**Answer**: Graph colouring is a graph theory assignment problem where colors are assigned to vertices such that no two adjacent vertices connected by an edge share the same color.

### Q4: How is graph colouring used in timetable scheduling?
**Answer**: Each class/subject is represented as a vertex, resource conflicts are represented as edges, and available time slots (Day + Period) are represented as colors.

### Q5: What does a vertex represent?
**Answer**: A vertex (node) in our conflict graph represents an individual class session or subject that needs to be scheduled.

### Q6: What does an edge represent?
**Answer**: An edge represents a conflict between two classes that prevents them from occurring in the same time slot (e.g., same teacher, same division, or same classroom).

### Q7: What does a colour represent?
**Answer**: A color represents a specific discrete time slot (such as `Monday P1` or `Tuesday P5`).

### Q8: Why did you use NetworkX?
**Answer**: NetworkX is a powerful Python library for creating, manipulating, and analyzing graph structures, calculating node degrees, and identifying graph edges cleanly.

### Q9: What is greedy graph colouring?
**Answer**: Greedy graph colouring processes vertices in a specific order (in our project, sorted by node degree descending—the Welch-Powell heuristic) and assigns the smallest available color integer not used by any neighboring vertex.

### Q10: What is backtracking?
**Answer**: Backtracking is a systematic Depth-First Search (DFS) algorithm that attempts to build a solution step-by-step. If a partial assignment leads to a dead end (no valid slot available), it undoes (backtracks) the previous assignment and tries an alternative choice.

### Q11: Why is backtracking required?
**Answer**: Greedy graph colouring is a heuristic and may not always guarantee a valid assignment under tight constraints. Backtracking performs systematic search to find a valid assignment when one exists.

### Q12: What is a hard constraint?
**Answer**: A hard constraint is a mandatory physical rule that MUST be satisfied for a timetable to be valid and feasible (e.g., a teacher cannot be in two classrooms at the same time).

### Q13: What is a soft constraint?
**Answer**: A soft constraint is a desirable preference that improves timetable quality but does not render the schedule invalid if violated (e.g., avoiding 3 consecutive lectures or teacher idle gaps).

### Q14: Give examples of hard constraints.
**Answer**:
1. Teacher Conflict (same teacher scheduled twice simultaneously)
2. Division Conflict (same student division scheduled twice simultaneously)
3. Room Conflict (same classroom scheduled twice simultaneously)
4. Teacher Unavailability
5. Room Unavailability
6. Room Capacity Insufficiency
7. Practical/Lab Requirement Mismatch

### Q15: Give examples of soft constraints.
**Answer**:
1. Too Many Consecutive Lectures ($\ge 3$ continuous periods)
2. Repeated Subject on the Same Day
3. Unnecessary Teacher Idle Gaps

### Q16: What is the quality score?
**Answer**: The Quality Score is an empirical numeric score from 0 to 100 calculated by deducting penalty points for hard violations (25 points each) and soft violations (5 points each):
$$\text{Quality Score} = \max(0, 100 - (\text{Hard Violations} \times 25) - (\text{Soft Violations} \times 5))$$

### Q17: Why is optimization required?
**Answer**: Initial feasible timetables generated by greedy or backtracking algorithms satisfy hard constraints but may contain soft constraint violations. Optimization improves schedule flow and quality score.

### Q18: What optimization approach is used?
**Answer**: We use **Hill-Climbing Local Search Optimization**. It starts from an initial feasible timetable, explores single-entry slot move candidates, evaluates neighbor quality scores, and accepts moves that yield positive score gains.

### Q19: What is algorithm comparison?
**Answer**: Algorithm comparison evaluates Greedy Graph Colouring, Backtracking, and Hill-Climbing Optimization on the exact same dataset to compare execution time, quality score, and violation counts.

### Q20: How do you compare algorithms fairly?
**Answer**: All algorithms run on identical dataset specifications (`sample_data.json`), share the same conflict graph, and are evaluated using the exact same constraint analyzer and timing functions.

### Q21: What is "Why This Slot?"
**Answer**: It is an explainable decision feature that inspects why an assigned slot is valid or preferred for a chosen subject by detailing all passed constraint checks (`✓`).

### Q22: What is "Why Not This Slot?"
**Answer**: It identifies the exact hard constraint failures (e.g., teacher conflict, division conflict, room occupied) or soft preference reasons why candidate slots were rejected (`✗`).

### Q23: What is What-If Simulation?
**Answer**: It is an interactive feature allowing users to test hypothetical class moves to target slots and dynamically view before vs after quality scores, hard/soft violation deltas, newly created violations, resolved violations, and recommendations.

### Q24: Does What-If Simulation modify the original timetable?
**Answer**: No. What-If Simulation creates a `copy.deepcopy()` of the timetable and performs all checks on the isolated copy, guaranteeing that the original baseline schedule remains untouched.

### Q25: What happens if no feasible timetable exists?
**Answer**: The backtracking solver terminates gracefully, returns `success=False`, and reports the number of assigned classes and backtracks without crashing or entering infinite loops.

### Q26: What is the time complexity of greedy colouring?
**Answer**: $O(V^2 + E)$, where $V$ is the number of subjects and $E$ is the number of conflict edges. Node degree sorting takes $O(V \log V)$ and color checking takes $O(V + E)$.

### Q27: What is the worst-case complexity of backtracking?
**Answer**: $O(K^V)$ in the worst-case, where $K$ is the number of available time slots and $V$ is the number of subjects.

### Q28: Why can backtracking be expensive?
**Answer**: Because the decision search space grows exponentially with the number of subjects ($K^V$). Degree-based variable ordering prunes the search space significantly.

### Q29: Why did you use Flask?
**Answer**: Flask is a lightweight Python web framework that easily integrates Python backend algorithms (NetworkX, NumPy/Matplotlib) with HTML/CSS templates and RESTful JSON API endpoints.

### Q30: Why did you use JavaScript/Chart.js?
**Answer**: JavaScript enables dynamic asynchronous API calls (`fetch()`) without full page reloads, and Chart.js renders interactive bar and doughnut charts for analytical dashboards.

### Q31: What is the role of the dashboard?
**Answer**: The Dashboard provides a centralized overview displaying top KPI cards (Total Classes, Conflicts, Quality Score), project module statuses, algorithm performance charts, weekly timetable summary grid, conflict graph statistics, and dynamic observations.

### Q32: What are the limitations of the project?
**Answer**: The current implementation reads dataset specs from JSON files rather than a relational database, and focuses on single-division scheduling per run.
